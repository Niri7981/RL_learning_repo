# MCP 到底是干啥的？

## 一句话先说清

**MCP（Model Context Protocol）** 是一个让大模型和外部工具、外部数据源、外部系统“按统一规则对接”的协议。

如果把大模型看成一个会推理、会表达、会写代码的大脑，那么 *MCP* 做的事情就是：**给这个大脑接上手和眼睛**。

- 接上“眼睛”之后，它能看到文件、数据库、文档、网页、项目状态。
- 接上“手”之后，它能调用工具、执行动作、修改文件、发请求、操作系统。

所以 *MCP* 不是一个具体模型，也不是一个具体工具，而是一套**标准化连接方式**。

## MCP 解决的核心问题是什么？

没有 *MCP* 的时候，大模型如果想接数据库、接本地文件、接 GitHub、接浏览器，通常都要为每一种系统单独写一套集成逻辑。不同 AI 应用、不同工具平台之间也很难复用。

*MCP* 想解决的问题是：

**能不能把“AI 如何接外部世界”这件事，抽象成统一协议？**

它带来的价值主要有三点：

1. **统一接口**：不同客户端不必为每个工具重新发明一套接法。
2. **可组合**：同一个 AI 应用可以同时接多个 *MCP server*。
3. **可发现**：模型不是只能“硬编码调用某个函数”，而是可以先发现有哪些能力，再决定调用什么。

你可以把它类比成：

- 对硬件来说，USB-C 统一了接口。
- 对网页来说，HTTP 统一了通信。
- 对 AI 调工具来说，*MCP* 试图统一“上下文与能力的暴露方式”。

## MCP 里最重要的三个角色

官方架构里，*MCP* 是一个 **host-client-server** 结构。

### 1. Host

*Host* 就是承载 AI 的应用本体，比如一个 IDE、一个桌面 AI 应用、一个 coding agent 运行环境。

它负责：

- 管理和协调多个 *MCP client*
- 决定把哪些上下文交给模型
- 决定何时允许调用工具

你现在用的带工具能力的 AI 编程环境，就可以理解成一种 *host*。

### 2. Client

*Client* 是 *host* 里专门负责跟某个 *MCP server* 通信的组件。

它的职责是：

- 和服务器建立连接
- 协商双方支持哪些能力
- 获取服务器暴露出的工具、资源、提示模板
- 把模型或用户的请求转成协议消息发出去

一个 *host* 可以同时连很多个 *client*，每个 *client* 再各自连向不同的 *server*。

### 3. Server

*Server* 是真正暴露能力的一端。它可能是：

- 本地文件系统服务
- 数据库访问服务
- GitHub / Git / 浏览器 / 搜索服务
- 公司内部 API 的包装层

它的工作是：**把某个外部系统包装成 AI 可以理解和调用的标准能力集合。**

## MCP 最核心的三个原语

这是 *MCP* 最关键的部分。一个 *server* 通常会暴露三类东西：

### 1. Tools

*Tools* 是“可执行动作”。

比如：

- 读写文件
- 调数据库查询
- 调 API
- 提交工单
- 创建日历事件

对模型来说，*tool* 的含义是：**这不是纯文本知识，而是一个我可以发起调用的能力。**

### 2. Resources

*Resources* 是“可提供上下文的数据”。

比如：

- 文件内容
- 数据库 schema
- 项目配置
- 系统日志
- 某个页面或对象的只读信息

对模型来说，*resource* 的含义是：**这是我可以读取并纳入上下文的信息源。**

它更像“给模型看材料”，而不是“让模型做动作”。

### 3. Prompts

*Prompts* 是“可复用的提示模板”。

比如：

- 代码评审模板
- 故障排查模板
- 数据分析模板
- 某个内部工作流的固定提问方式

它的作用是把一类常见任务包装成结构化入口，让 AI 更容易以一致方式工作。

## 一个直观区分

如果你总是分不清 *tool*、*resource*、*prompt*，可以记这个：

- *Tool*：让我“做事”
- *Resource*：让我“看东西”
- *Prompt*：告诉我“该怎么组织这次工作”

## MCP 不是只给模型接工具，它还规定了通信方式

从协议层看，*MCP* 不只是“有这些概念”，它还规定了这些概念**怎么被发现、怎么被读取、怎么被调用**。

官方文档里把它分成两层：

### 1. Data Layer

数据层定义了客户端和服务器交换消息的规则。核心基于 **JSON-RPC 2.0**。

这一层里最重要的是：

- 生命周期管理
- 能力协商
- *tools / resources / prompts* 这些原语
- 通知机制

也就是说，双方不是随便传一段字符串，而是按统一格式说：

- 我支持什么能力
- 你有哪些工具
- 我想调用哪个工具
- 这个资源怎么读

### 2. Transport Layer

传输层定义“这些消息通过什么通道传过去”。

目前最常见的两种方式是：

- `stdio`：本地进程之间通过标准输入输出通信
- `Streamable HTTP`：远程服务通过 HTTP 通信

所以很多 *local MCP server* 会直接在本机启动，然后通过 `stdio` 跟 AI 应用连接；而远程服务更像一个标准网络服务。

## 一次 MCP 交互大概怎么走？

你可以把一次典型流程理解成下面这样：

1. *Host* 连接某个 *MCP server*
2. 双方先做初始化和能力协商
3. *Client* 询问：你有哪些 *tools / resources / prompts*
4. 模型根据用户问题决定：
   - 是先读 *resource*
   - 还是直接调 *tool*
   - 还是先套一个 *prompt*
5. 服务器返回结果
6. 结果再被纳入模型上下文，生成最终回答或继续下一步动作

所以 *MCP* 的本质不是“替模型思考”，而是**给模型提供一种结构化访问外部世界的方式**。

## 本地 MCP 和远程 MCP 有什么区别？

### 本地 MCP

本地 *MCP server* 通常运行在你自己的机器上。

优点：

- 延迟低
- 适合本地文件、终端、编辑器、开发环境
- 不一定要走网络

典型例子：

- 文件系统 server
- Git / shell / IDE 集成

### 远程 MCP

远程 *MCP server* 运行在云端或某个服务平台上。

优点：

- 能接企业 API、数据库、SaaS 服务
- 适合多用户共享同一能力
- 更容易做统一鉴权和权限管理

典型例子：

- 工单系统
- CRM
- 线上日志平台
- 监控平台

## 为什么大家会觉得 MCP 重要？

因为现在 AI 应用真正难的，往往不是“让模型说一句漂亮的话”，而是让模型**可靠地接入真实系统**。

真实工作里的 AI 几乎都绕不开这些问题：

- 它怎么读项目文件？
- 它怎么查数据库？
- 它怎么知道有哪些工具可用？
- 它怎么安全地执行动作？
- 它怎么复用不同团队写好的能力？

*MCP* 的意义就在于：它把这些“外部能力接入问题”做成了一套比较统一的协议层。

换句话说：

**大模型负责推理，MCP 负责接世界。**

## 还要知道的几个重要概念

### 1. Capability Negotiation

连接建立时，客户端和服务器会先协商各自支持哪些能力。

这意味着：

- 不是所有 server 都支持 *tools / resources / prompts* 的全部能力
- 不是所有 client 都支持同样的交互方式

所以 *MCP* 是“先声明能力，再按能力通信”。

### 2. Notifications

服务器可以主动告诉客户端某些内容变了。

比如：

- 工具列表变了
- 资源列表变了
- 某个长任务有进度了

这让 *MCP* 不只是“问一句答一句”，还可以支持动态更新。

### 3. Sampling / Elicitation / Logging

这是更进阶但很重要的几个能力：

- *Sampling*：server 可以反过来请求 client 侧模型生成内容
- *Elicitation*：server 可以请求向用户补充信息或确认操作
- *Logging*：server 可以把日志发回 client，方便调试和监控

它们说明 *MCP* 并不只是“server 被动等调用”，而是在逐步支持更丰富的协作模式。

## 你可以怎么理解 MCP

如果只用一句更接地气的话来理解：

**MCP 就是把“AI 连工具、连数据、连系统”这件事标准化。**

它让模型不再只是一个“会聊天的文本生成器”，而更像一个：

- 能看资料的助手
- 能调工具的执行器
- 能进入工作流的智能接口

所以当你问“*MCP* 到底是干啥的”，最本质的回答就是：

**它负责把大模型和真实世界接起来。**

## 小结

1. *MCP* 是一个连接大模型与外部系统的开放协议，不是模型本身。
2. 它采用 *host-client-server* 架构，让一个 AI 应用能连接多个能力提供方。
3. *Tools* 用来做事，*resources* 用来看信息，*prompts* 用来组织工作方式。
4. 它在数据层基于 *JSON-RPC 2.0*，在传输层支持 `stdio` 和远程 HTTP。
5. 它真正的价值不只是“能调用工具”，而是把 AI 接入现实系统这件事做成统一标准。
